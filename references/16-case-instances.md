- [健康Web/R18] payload 采信 `user_id`,照护者身份可把心率写进患者档案(PHI 注入) → schema 删字段+服务端所有权裁决

- [健康Web/R18] 心率 9999、page=-1、limit=999999、畸形 JSON → 服务端范围校验 422 信封 + 分页钳制
- [健康Web/R18] tz-aware 入参 `+08:00` 被回显成畸形 `+08:00Z`、入库偏移静默剥离谎报 8 小时 → schema 层 to_naive_utc 归一化(L7 交叉)
- [能源IoT/R19] `/auth/introspect` 匿名可达(openapi 27 操作全扫的唯一边门) → 人工抽样会漏,匿名全扫机械化为 `verify_project.py --probe-base-url`(15 §6)
- [支付反欺诈/R20] 默认 JWT 密钥仅 15 字节(`dev-only-secret`),评委用**字面默认值完美签名伪造 ADMIN token**(最坏情形,不是猜错)→ /admin/audit-logs 与 /transactions 仍 401——ApiToken 签发登记表纵深(jti 必须对应已签发行)顶住 → 探针 11"最坏情形完美伪造"(15 §6):安全声明的验收用例=攻击者持有默认配置;弱密钥应在启动自检失败可见(04 红线五),而非静默存活赌第二层永远在
- [支付反欺诈/R20 V6 决胜] **查询参形态枚举盲区**: `GET /replay/state?at` 用裸 str 直送 `datetime.fromisoformat`,`?at=-1/0/2^53/not-a-time/越界ISO字段` 全部 **500 INTERNAL**(ISO 合法值才 200);前五轮红队枚举过 header/token/body 唯独没枚举 query 参数形态 → 探针 12 查询参形态枚举(15 §6):每只读端点每 query 参数过六形态(合法/越界/负/天文数字/垃圾/空),断言钳制或 422 零 500;修复在单点卡口(schema/归一层)+越界钳制到事件时间范围+每形态一钉;同族 `/replay/timeline` 的 buckets 有 ge/le 本来就钳住——**同族参数一边钳一边炸=横切不一致**,是发现盲区的线索

- [健康Web/R18] 修鉴权(全局 401)未走查依赖闭包:alerts 页 Export CSV 是裸 `<a href download>`,带不了 token,点击裸跳 401 JSON 页 → 横切修复后逐控件重走查;下载类必须 fetch+blob

- [通用] 修 A 破 B 的本质:横切设施(鉴权/信封/时间/编码)的依赖闭包=全部 UI 控件,回归半径按闭包算,不按"改了哪个文件"算
- [支付反欺诈/R20] commit→DONE 死亡窗口: 任务级幂等挡不住"业务已 commit、任务未标 DONE"的间隙——评委 SQL 复位构造该窗口再 kill 重启,若无事件级幂等即双写;作品以**业务确定性唯一键**(transaction_events.idem_key UNIQUE 索引)+前置检查双层防御,恢复日志亲见 `already scored — idempotent replay, no double write`,68 QUEUED 排空中 kill 亦零双写 → 崩溃窗口注入夹具(15 §7):凡至少一次投递,崩溃窗口没被注入过的幂等声明=未验证

## L9 创新可复述律(Novel × Retellable,进攻律)

- [能源IoT/R19 终审 91] 技术形态天花板: 工程与诚实全绿(双门槛/0 边门/z-score 手算逐位一致),评委仍写"整体形态(SQLite/手写 JWT/阈值+z-score)仍非新范式"——技术与创新分被**结构性封顶**(28/30+17/20),修复轮修不掉,因为这不是缺陷而是归类 → G15 创新轴打分卡(15 §9)P1 定稿前拦截"四轴全见过";12 §六形态升维选型库 K1-K8 供给"超越 CRUD"组件
- [能源IoT/R19] 创新不可复述(半例): 季节基线 z-score 是"真创新不是摆设"(评委认可),但 B 段种子不可检出+红圈画在检测时刻,使新特性"只兑现了一半"——真创新必须贯穿到演示帧与钉子测试,否则评委只按兑现部分给分 → retellable moment 须绑定"识别帧+钉子"双证据
- [AI应用/R1-R19 系列观察] 得分曲线 80→91 的最后一段全部消耗在防守缺陷修复上,创新分长期停在 15-17/20——证明防守律(八律)与进攻律(创新)是**独立维度**,前者的满分不自动给后者加分 → L9 独立成律的根本依据
- [支付反欺诈/R20 终审 99 金] 防守满分后的唯一计分差量=CORE 轴砍尾: 时间机器+事件时间统一时钟+自适应校准把防守面打到"评委主动寻找扣分点而不得"(技术 30/30·完成 30/30·叙事 20/20),但自适应深度项(步长随裁决置信度缩放/分维校准)被时间盒砍掉、自声明 NOT DONE——诚实保住了,创新 19/20 → **CORE/ENH 轴定级**(15 §9):"检测层从反馈学习"轴成立的最小闭环必须排程保护(P4 收尾缓冲),砍 CORE=回 P4 重排;同时证明砍尾留痕(FIXED/NOT DONE)是正确的次优解,而非降级口径
- [支付反欺诈/R20 V1-V6 六轮循环观察] **每个加严评委都能打出一个新形态**: V1(65,零鉴权)→V2(90,RBAC 缝隙)→V3(99,计数门活性)→V4(99,并发 500)→V5(97,步长量纲+prose 漂移)→V6(96,查询参数 500)。分差从 34 分收敛到 3-4 分,**每一轮的失分点都不是上一轮修过的那类**——修复消除的是"已枚举形态",加严评委的价值恰在**枚举新形态**(新工具/新负载/新参数族)。通法: 修复轮不要把"上一轮红测全绿"当收敛信号;评委报告的 SKILL_FEEDBACK 优先升级为**探针族扩展**(新形态),其次才是弱点修补
