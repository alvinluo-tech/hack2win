# P2 深度市场调研 — 三轮对抗性辩证调研与立项护城河 (02)

> **核心原则**: **坚决取缔“单轮搜索、草率拍板”的伪调研！**
> 任何未经红队摧毁性审判的选题，本质上都是开发者的“自我感动”与“认知偏见”。

## 二、逐轮执行细则与方法论

### 1. Round 1: 广度全景扫描 (Landscape Sweep)
- **目标**: 摸清全球范围内谁在做类似的事，做到什么程度，开源生态到了哪个版本。
- **检索渠道与指令**:
  - **前沿产品与黑客松作品**: 使用 Exa 或 WebSearch 检索：
    `site:devpost.com "winner" <关键词>`, `site:producthunt.com <关键词>`, `site:ethglobal.com/showcase <关键词>`；
  - **顶级开源生态**: 检索 GitHub 活跃仓库：
    `gh search repos "<关键词>" --sort stars --limit 15`，查阅开源项目的 README、Release 频率、最近 Issue 争议。
- **输出产物**:
  - 整理出 **≥ 3-5 个真实竞品/基准项目** 矩阵（名称、官网/仓库链接、核心卖点、当前局限性）。
  - 没有直接竞品时，必须找到**行为替代品**（如“目前用户在靠 Excel 表格人工核对”、“在群聊里靠 @ 机器人手动协作”）。替代品是路演故事的最佳对比锚点。

### 2. Round 2: 红队压力测试与死亡墓地反思 (Red-Team Graveyard Analysis)
- **目标**: **假设这个项目在市场上必然会死，找出它死在何处！** 严禁自欺欺人。
- **检索渠道与方法**:
  - 检索负面讨论与阵亡项目：
    `site:news.ycombinator.com "<关键词> failed" OR "<关键词> problem"`, `site:reddit.com <关键词> complaints OR sucks`；
  - 检索同领域停更的 GitHub 仓库或被收购/关停的项目。
- **红队灵魂四问 (必须在 `02-market.md` 逐条书面作答)**:
  1. **“大厂如果做这个，或者开源模型升级一个版本，你的价值是否瞬间归零？”**（防薄套壳）；
  2. **“历史上有没有人尝试过？他们为什么停更或者倒闭了？”**（防重复前人已验证的死路）；
  3. **“这个技术方案最脆弱的单点在哪里？”**（API 速率限制？冷启动延迟？数据标注成本？多端兼容性？）；
  4. **“如果这个痛点真的如此致命，用户现在为什么能忍受替代方案？”**（检验是否为凭空捏造的伪需求）。
- **产出对抗矩阵 (Thesis vs Antithesis)**:

| 维度 | Thesis (正方乐观主张) | Antithesis (反方红队死亡攻击) |
|---|---|---|
| **需求真实性** | 用户需要实时多代理协作可视化 | 绝大多数人只关心最后结果，不在乎小人怎么跑 |
| **技术可行性** | 浏览器 WebGPU 端侧推理免除服务器成本 | 客户端机器显卡参差不齐，大模型权重下载耗时劝退用户 |
| **竞争护城河** | 我们界面极具创新且交互丝滑 | 纯 UI 创新极易被模仿，若无底层协议/状态机沉淀，2 周内被复制 |

### 3. Round 3: 升维综合与护城河锁定 (Synthesis & Unfair Moat)
- **目标**: 正面迎击 Round 2 的反方攻击，提炼出不可动摇的立项依据。
- **必须达成的四项要素**:
  1. **不讨巧却痛感极强的切口 (The Unglamorous Wedge)**:
     - 避开泛泛的表面功能，切入深水区中间件（如：不解决“帮用户生成代码”，而解决“代码生成后的自动化沙盒测试与回滚仲裁”；不解决“聊天”，而解决“智能体调用的计费与幂等结算”）。
  2. **绝对差异化声明 (通过“遮名测试”)**:
     - 模板：`现有方案往往 [竞品做法]，但在 [核心缺陷场景] 下必然失败/成本极高；[产品名] 通过 [底层独特技术组合]，实现了 [别人无法给出的核心保障/结果]。`
     - **遮名测试检验**: 将产品名称遮住，该声明仍能精准指认本产品，且竞品无法直接套用。
  3. **Why Now 三大拐点**:
     - **技术拐点**: 过去 6-12 个月什么刚成熟/降价/发布？（如 React 19 / Tailwind v4 / WebGPU 普及 / 某开源轻量模型发布）；
     - **需求拐点**: 市场上发生了什么趋势性痛点？（如 AI Agent 数量爆发导致的执行混乱、企业合规审查收紧）；
     - **生态拐点**: 主办方或开源社区推出了什么新基建/SDK？
  4. **痛点数据证据链与新鲜度标准**:
     - 必须列出 3-5 条具备来源链接的引文或权威行业数据（如 Gartner, CNNIC, GitHub 官方报告）；
     - **新鲜度底线**: 至少 1 条证据来自近 24 个月内，旧数据仅用于对比趋势。

## 三、Traction 实证方案 (真实用户加分项)

“真实用户使用过 (Some real users have touched this)” 是顶级黑客松的最强加分项（核验案例证明 traction 可跨维度碾压纯理论项目）：
- 在 `02-market.md` 中写明 **赛期内获取 ≥ 5-10 个真实用户反馈的执行方案**：
  - 渠道：目标开发者社群（Discord/Reddit/微信群/V2EX/同学内测）；
  - 触达话术与试用链接；
  - 预期收集的反馈截图或日志留存计划。

## 四、提交前证据卫生 (全量链接机器核验)

所有在调研中引用的外部 URL，在 P6 提交前必须通过自动化脚本核验，严禁出现 404/403 断链被评委抽查扣分：

```powershell
# 对 02-market.md 中的全部外部链接执行活体连通性扫描
Select-String -Path 02-market.md -Pattern 'https?://[^\s\)\|"]+' -AllMatches |
  ForEach-Object { $_.Matches.Value } | Sort-Object -Unique | ForEach-Object {
    $code = curl.exe -s -o NUL -w "%{http_code}" -L -m 15 -A "Mozilla/5.0" $_
    if ($code -eq "200") { Write-Host "[200 OK] $_" } else { Write-Host "[$code FAIL] $_" }
  }
```
- 若检测到 404 或被屏蔽拦截：立即更换为现行官方页面、Wayback 存档页，或删除失效断言。

## 五、“AI 在哪”三层深度预演 (AI 赛道必答题)

如果参赛赛道包含 AI/Agent，但核心算法涉及确定性规则或传统工程：
在 P2 结束前必须在文档中固化三层标准答辩词，防止评委提问时哑火：
1. **第一层 (真正在哪)**: 精确指出 AI 模型或智能体逻辑运行在系统哪个具体模块（精确到服务函数与提示词文件）；
2. **第二层 (为何确定性优先)**: 阐明核心结算、安全策略、数据流为何采用状态机与确定性规则（解释为何不能把资金与生产安全交给产生幻觉的 LLM，彰显架构成熟度）；
3. **第三层 (模型扩展路径)**: 展示系统为后续引入更强大云端模型预留的抽象端口与演进路线。
