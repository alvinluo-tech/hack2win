# P0 命题解码 — 把考卷答案找出来

> 目标:产出 `00-brief.md` 一页纸。时间盒 5%。**没做过 P0 的头脑风暴是赌博。**

## 为什么先解码

评委按主办方公布的评分标准打分;主办方办比赛是为了得到什么东西(人才/生态/内容/案例/招新)。切题性在几乎所有 rubric 里都是一票否决项。你要做的是"在主办方想要的地方,给出超预期的东西",而不是"做一个自己想做的东西然后蹭题"。

## 解码四问(逐一回答,写进 brief)

### 1. 主办方是谁?TA想要什么?
- 大厂办赛:推自家技术栈/平台采用(用它家 SDK/API/模型是隐性加分,甚至是硬性赛道要求)、物色开发者、制造内容案例
- 政府/园区办赛:落地项目、产业方向契合(如 AI+制造/AI+医疗)、本地团队
- Web3 基金会:生态项目、协议采用、TVL/用户增长潜力
- 高校/社区:学习氛围、参与度、学生作品
- **动作**:在 brief 里写一句"本次比赛,主办方最想在颁奖台上展示的作品是____"。

### 2. 评分标准怎么逆向?
- 找官方 rubric(往届页面/FAQ/规则PDF);找不到就按 [07-judging-rubrics.md](07-judging-rubrics.md) 的通用权重估计
- 把每个评分维度翻译成"我该怎么挣这个分":
  - 创新性 → 别人没做过的组合/角度(靠 P2 调研证明"别人没做过")
  - 技术难度 → 至少一个评委能看懂的硬点(不是堆名词)
  - 实用性/影响 → 真实场景+真实用户画像(哪怕是模拟的)
  - 完成度 → demo 能跑,不是 PPT
  - 演示/表达 → 3分钟讲清楚+演示冲击力
- 标出权重最高的两条,后面所有争论以这两条为准绳。

### 3. 往届冠军长什么样?
- 搜往届获奖页(Devpost winners tab / 官方新闻稿 / B站/YouTube 回放)
- 归纳 3 个规律:题材偏好?完成度标准?演示风格(狂炫技术 vs 讲故事)?
- 避开"往届已获奖的同类idea"——除非你有明显代差。

### 4. 约束与隐藏坑?
- 参赛资格(学生限定?地区?年龄?)、组队要求、开源要求、AI使用披露要求
- 提交物清单(代码/视频/文档/表单)、知识产权条款
- **赞助商技术可得性预检(大厂赛必做)**:比赛要求/期待用赞助商技术栈时,P0 当天就回答——"我们真能用上吗?"(账号能否注册/云额度要审批吗/需要真机 GPU 吗/免费 tier 够 demo 吗)。**能→当天申请,把等待审核放在时间线最前端;不能→写明缓解策略**(诚实交底+v2迁移路径+厂商中立等价物),或考虑换赛——赞助商契合是主办方隐性问题,"零使用"会在评审桌上封死上限
- 这些直接抄进 SUBMISSION.md。

## 产物模板(00-brief.md)

```markdown
# 命题解码卡 — <比赛名>
- 主办方/赞助商: / 他们想要:
- 主题/赛道原文: (抄原文,别意译)
- 评分维度+权重: (表格,标出最高权重项)
- 往届冠军速览: (3条规律)
- 硬约束: (资格/提交/格式/期限,含时区!)
- 赞助商技术预检: 能否真用上(账号/额度/硬件)→申请动作或缓解策略
- 评委画像: (构成/技术背景/可能偏好)
- 一句话战略: 我们要赢得____分,做法是____
```
