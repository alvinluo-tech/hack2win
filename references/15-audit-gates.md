# 15 · 审计门与回环路由 (Audit Gates & Loop-Back Routing)

> **本文件解决什么问题**: "验收不通过就重做"是废话——重做什么? 谁来做? 重做几轮?
> 本文件把每次验收产出统一为 **BLOCKER / WARNING / INFO** 三级发现, 并为每一类 BLOCKER
> **指名道姓地规定回环目标阶段**, 让"反思优化"从一句口号变成一条可执行的边。
>
> **门与法则的关系**: 门是**法的执法器**——每道门执行 SKILL.md「第一性原理九律」中的一条或多条;**法则没有执法器=法则不存在**。映射: G5/G8/G16→L1 名实一致 · G12→L2+L3+L4 · G13→L5 运行时存在 · G2/G3/G4/G7 红测与证据纪律→L6 验证的验证 · 信封/时间/鉴权类单点契约设计→L7 · G10 冷启动与回归纪律→L8 变更闭包 · **G15→L9 创新可复述(唯一进攻门)** · G14→L1+L6。案例级证据索引见 [`16-case-instances.md`](16-case-instances.md)。

---

## 1. 为什么需要三级严重度

PaperSpine 的审计脚本(`integrity_audit.py` / `artifact_check.py`)统一返回:
- **BLOCKER** → 存在即 `exit 1`, 流程禁止向下游推进;
- **WARNING** → 记录但不阻断, 进入下一轮必须消化;
- **INFO** → 确认性信息, 用于证明"这个检查真的跑了"(而非跳过)。

**为什么必须有**: 若只有"通过/不通过"二元结果, 长会话中 agent 会把真实缺陷降级为"小问题下次再说",
最终交付时无人记得。三级模型的价值在于**INFO 层的存在感**——它让"我检查过了"必须留下痕迹,
而不是静默跳过(对应 07 死法"证据卫生欠账")。

## 2. 审计门清单与产出物

每个门都必须: ① 有确定性脚本或明确的人工步骤; ② 产出落盘到 `hackathon-run/evidence/`; ③ 用三级结论收尾。

| 门 | 触发时点 | 执行者 | 产出物 | 阻断条件 |
| :--- | :--- | :--- | :--- | :--- |
| G0 配置门 | P0 结束 | 主线程 | `run-config.json` 通过 schema 校验 | 缺任一 required 字段 |
| G1 命题门 | P0 | 主线程 | `00-brief.md` 评分逆向表 | `rubric_source=published` 却无逐项逆向 |

## 3. 回环路由表 (核心机制)

发现 BLOCKER 后**不允许自由发挥修复方向**。按发现类型查下表, 回环到指定阶段:

| BLOCKER 类型 | 典型发现 | 回环目标 | 回环动作 | 允许的重试上限 |
| :--- | :--- | :--- | :--- | :--- |
| `CONFIG` | run-config 字段缺失/矛盾 | **P0** | 补全并向用户重新确认 | 2 |
| `THEME` | 产物不切题, 评委看不出关联 | **P0 → P1** | 重读命题卡, 重收敛 idea | 1 (再失败必须换赛道或换题) |
| `EVIDENCE` | 竞品链接 404、痛点数据无源 | **P2** | 重做调研或用替代证据, 重跑 link-check | 3 |
| `SCOPE` | 交付等级与时间预算严重不匹配 | **P3** | 重定 MoSCoW 与演示脚本, 重新冻结 tier | 1 |
| `ARCH` | 分层穿越、单文件 >300 LOC、缺迁移 | **P4** | 局部重构该模块, 重跑 G4 | 3 |
| `COMPLEXITY` | LOC/表/端点/组件数不达标 | **P4** | 补齐缺失子系统(不靠灌水注释) | 2 |
| `ASYNC` | 耗时调用在请求线程内 | **P4** | 抽取到 Worker, 前端改轮询/SSE | 2 |
| `VISUAL` | 溢出、裁切、重叠、肉眼惊悚 | **P5** | 修样式, 重跑 G6 并留前后对比截图 | 5 |
| `COMPONENT` | V-CLIP / TINY 命中 | **P5** | 换成熟组件库控件(禁手搓复合控件) | 5 |
| `FAKE` | 硬编码伪高光、动效与真值源脱节 | **P4** | 改为 DomainEvent 单向投影 | 2 |
| `SPONSOR` | 纸面适配器、无运行日志 | **P4** | 真跑一次并留日志, 或诚实降级声明 | 2 |
| `PITCH` | 3 分钟内讲不清价值 | **P6** | 重写故事弧, 重排 demo 脚本 | 3 |
| `CORE-AXIS` | P4 收尾缓冲耗尽而 CORE 创新轴未完成 | **P4** | 换更小可行实现路径完成 CORE 轴; 仍不完=SCOPE 级决策(诚实降级+用户确认), 禁止静默砍尾 | 2 |
| `DRIFT` | G17 活门在提交前或复跑时变红 | **P6** | 重算运行态→同步全部文档数字→复跑 `--check` 至 exit 0, 留前后输出 | 3 |

**回环纪律**:

1. **每次回环必须留痕**: 在 `hackathon-run/devlog.md` 追加 `AUDIT-LOOP` 记录(门名、级别、发现、回环目标、修复摘要、重跑结果)。
2. **同一 BLOCKER 连续两轮未修复 → 升级为"根因问题"**: 停止局部修补, 组织一次根因分析, 必要时回退到上一个稳定里程碑。
3. **达到重试上限仍失败**: 不得继续消耗预算硬修。必须二选一——(a) 用降级方案诚实交付并写明限制; (b) 向用户升级求助。**禁止静默交付已知缺陷**。

## 4. 证据留痕规范

每份证据文件的首行必须是头部注释, 格式:

```
# GATE: G6 视觉门 | AT: 2026-10-07T14:22Z | RESULT: BLOCKER
# FINDINGS: 390px 视口下 Sidebar 溢出 12px
# LOOP-TO: P5 | RETRY: 1/5
```

**为什么强制头部**: 长会话后期,"这个日志是哪次跑的、什么结论"会彻底失去上下文。
头部把时间、结论、回环目标一次性钉死在文件里, 使任何后来者(包括下一轮验证 agent)无需追问即可接手。

**禁止事项**:

- 禁止伪造 INFO 来证明"检查过了"——INFO 必须对应一条真实执行的命令及其原始输出;
- 禁止只保留最终通过结果而删除失败证据——失败记录是"迭代"这一主张的唯一证明;
- 禁止把截图存到 `iterations/` 之外(验收脚本按目录约定收集)。

## 5. 与验证子代理的接口

独立验证 agent(不参与构建、只负责验收)的输入契约:

1. **必读**: `run-config.json`(判定基准)、`SKILL.md` 验收门清单、本文件的回环路由表;
2. **必查**: `evidence/` 下每个门的产出物是否存在且头部结论为 PASS;
3. **必做**: 亲自重跑 G3 / G4 / G7 三个机械脚本(不采信既有日志), 以及**真实浏览器点击**核心演示链路;
4. **必产出**: 一份带三级严重度的验收报告, 明确列出所有 BLOCKER 的回环目标;
5. **禁止**: 依据 agent 的自我陈述打分。**只认机器输出与真实点击结果**。

> **一句话总结**: 验收不是"你做得怎么样", 而是"哪扇门红了、红的该退回哪里、退了几轮、现在还红不红"。

## 6. G12 红队安全门细则 (实战: 评委 30 秒 curl 证伪"隐私优先")

**触发条件**: brief 含"隐私/医疗/健康/多租户/协作"任一字样,或作品存在 ≥2 种用户角色 → **强制执行**,一票先跑。
**十探针**(逐条 curl,记录请求与响应到 `evidence/redteam-probes.log`):

1. 无 token 访问每个业务端点 → 必须 401(逐端点过 openapi.json,不许抽样)
2. 伪造/过期 token → 401 且 error_code 区分
3. 跨用户读:用户 B 按 ID 读用户 A 的资源 → 403 或 404(且列表不可见)
4. 跨用户写:用户 B PATCH/DELETE 用户 A 的资源 → 403
5. 客户端所有权注入:payload 塞他人 user_id → 服务端裁决归属,数据落在会话用户名下
6. 角色自述:新会话自述高权角色(caregiver/admin)→ 白名单或降级,不得直接越墙
7. 范围外值:生理/业务极限值(心率 9999、数量 -1)→ 422
8. 畸形 payload:类型错误 JSON → 422 且入统一错误信封(与业务 422 同形)
9. 畸形分页/查询:page=-1、limit=999999 → 钳制或 422,不 500
10. 审计归因:上述每个写操作在 audit 日志中的 actor 是否为真实会话用户(而非静默默认用户)
11. **最坏情形完美伪造**: 假设攻击者**持有字面默认配置**——用默认密钥/默认凭据**正确签名**一个高权 token(或携带出厂默认凭据)→ 必须仍被第二层防线拦下(签发登记表/白名单/会话绑定),或服务在弱配置下**拒绝启动/显式拒绝高权操作**。“攻击者猜错密钥”不构成安全证据,“攻击者拿对了默认配置仍越不过”才是。
12. **查询参数形态枚举**(R20 V6 决胜终审实弹): 红队历来枚举 header/token/body 形态,唯独 URL query 参数是盲区——实测金奖作品 `?at=-1 / at=0 / at=2^53 / at=<垃圾串> / at<ISO字段越界>` 全 500(裸 str 直送解析器)。**执法**: 每个只读端点的**每个** query 参数至少过六形态(合法/越界/负/天文数字/垃圾串/空),断言“钳制或 422,零 500”;时间/分页类参数(at/hours/limit/page/window)必查;每个非-500 断言一条钉子。**钳制语义**: 越界→收敛到合法域(远过去→首事件),非 ISO→422,空=无参;只允许在 schema 层或单一卡口归一,散点 try/except 不算。

**3×3 隔离穷举矩阵**(端点级 401 全绿 ≠ 隔离无洞——R18 实测 32 端点 401 全过但 care-plans 在"患者×他人资源×写"格子上是空的):

| 资源类型 \ 操作 | 读(list+get) | 写(create/update) | 删(delete) |
|---|---|---|---|
| 患者私有资源 | 本人✓ 他人✗ 照护✓ | 本人✓ 他人✗ 照护(按产品口径) | 本人✓ 他人✗ |
| 共享/临床资源 | 按 role 口径 | 按 role 口径 | 按 role 口径 |
| 系统资源(审计/配置) | 按口径 | 通常✗ | 通常✗ |

每个"✗"格子必须有一条**钉住它的测试**(test 名即探针名)。**权限/隔离变更的完成定义(DoD)**: 一处权限收口的"修复完成" = **格子矩阵测试绿 + 文档矩阵同轮重写**, 二者缺一不算修复——只改代码不改文档(或反之)等于把幽灵面留给评委。qa.md/README 中的端点×角色矩阵必须与测试同一次提交更新。

**修复类提交的铁律(修复轮三件套,缺一不算修复)**: 每个缺陷的修复必须同时交付 ①**声明**——改了什么、语义是什么(一句人话);②**钉子**——钉住它的回归测试名(无钉子的修复按表面修补预判);③**活体**——运行时证据(复跑命令+输出或截图),证明修复在真实进程里生效而非只活在测试里。三件套齐备前,修复轮不允许提交。**钉子断言必须与注释/文档意图逐对象对齐**: 断言弱于意图(如注释说"两段都检出"、断言只写 `>=2` 被单段虚满足)时,注释承载强声明、断言给假信心——逐对象写断言,禁止可用其他对象虚满足的聚合断言。

**OpenAPI 匿名全扫(可机械化)**: 解析 `/openapi.json` 的**每一个操作**,匿名请求,断言除显式白名单(/health、登录/注册、docs)外全部 401——人工抽样会漏掉个别端点的边门(R19 实测 introspect 匿名可达即漏网)。机械化形态: `python verify_project.py --project-path <app> --probe-base-url http://127.0.0.1:<port>`(服务在跑时自动执行该扫描,离线时降级 WARN)。

**契约驱动扫描(幽灵面的通解)**: 一切边界检查(匿名 401/CORS/安全响应头/错误信封/限流)都应**从解析出的运行时契约**(openapi.json、路由表、配置对象)驱动,严禁手列端点清单——手工清单必然漂移,漂移处就是幽灵面。匿名全扫是第一个实例(见上),同一模式推广: 从契约枚举全部操作后,逐操作断言目标不变量。**凡是文档或代码里手写的"端点/能力清单",一律视为嫌疑对象,必须与契约机器枚举结果对账。**

**声明面可达性扫描(幽灵面检测,归 L1 执法)**: 代码与文档中声明的每个状态/档位/能力常量(Literal 枚举值、状态机状态、UI 徽章文案、配置开关),必须回答两个问题: **谁写入它?哪条测试钉住它?** 答不出=幽灵声明面(声明了但运行时不可达/不生效),评委实测即穿帮("四态实为三态"、"冷却 10 分钟"从不生效)。每发现一个: 实现写入路径+补钉子测试,或删除声明并文档交底。逐条产出进 `evidence/narrative-audit.md`。

**门槛自身不得吞失败**(实战:某轮 gate 只 `\d+ passed` 计数,套件 "1 failed, 39 passed" 照样 17/17 绿):任何解析 pytest/测试输出的检查项必须**同时断言 `N passed` 且 `0 failed` 且 `0 error`**;每个机械门至少**红测一次**(故意注入一个失败,亲眼看到门变红、退出码非 0),没红过的门不算验证过。

## 7. G13 运行时行为门细则 (实战: "提醒子系统"代码齐全但从未运行)

- **规则**: 00-brief 标题里的每个产品名词(提醒/追踪/告警/同步/队列…)必须回答:"它在**运行时**由谁拉起?"——start 脚本进程、API lifespan 内置任务、或独立 worker 三选一。
- **证据**(缺一即 FAIL):
  1. 启动后日志心跳(如 `reminder.dispatch tick=N sent=M` 持续滚动);
  2. **状态翻转实测**: 造一条将到期数据(注意时区口径!),轮询观察 pending→sent/next 状态在 ≤3 分钟内真实翻转;
  3. UI 联动:运行时产物在界面上有真实投影(倒计时/计数与 API 同刻一致)。
- **反模式**: "worker 文件存在且有测试"≠运行;e2e 只断言接口 202 ≠ 子系统活着。
- **崩溃窗口注入(凡"至少一次"投递必测)**: 队列/worker/重试流水线在进程死亡与状态落库之间存在双写窗口——任务级幂等挡不住"业务已 commit、任务未标 DONE"的间隙。要求: ①事件/副作用表带**业务确定性唯一键**并以 DB 唯一索引兜底(前置检查为主、索引兜底为辅的双层防御);②**崩溃窗口做成可注入夹具**——至少一种亲手构造(排空中 taskkill / SQL 复位构造 commit→DONE 窗口)被测试或演练覆盖,复跑后断言"每个业务对象的事件恰 1 条、全局重复=0、恢复日志可见"。崩溃窗口没被注入过的幂等声明按未验证预判。

## 8. G14 一致性门细则 (claim lint + 证据时点)

**claim lint**(跨文档机械核对,发现即 FAIL):
1. **词表绑定验证动作**: "只读/全量/实时/pinned/实测/加密"每条 claim 必须能指出"哪个探针/测试/日志证明它",指不出即删改措辞;
2. **跨文档交叉一致**: README ↔ SUBMISSION ↔ 门槛日志的数字(LOC/端点数/测试数/门槛通过数)逐一相等;
3. **验证指引路径真实存在**: 文档让评委跑的每条命令、每个日志文件路径,提交前亲手跑一遍(含 stdout/stderr 归属——Python logging 默认走 stderr);
4. **证据时点一致性**: 全部 evidence 文件时间戳 > 末次代码改动;gate 输出/census/提交书三处 LOC 同口径同数值;记录工具版本;
5. **全称量词自查**: 凡写下"零漂移/全部/每个/所有"级别的声明,提交前对**同一事实**做一次 grep 逐处核对——实战同一事实(日志路径写错文件)连续三轮在文档不同位置漏网;
6. **证据清单 manifest**: `evidence/manifest.json` 记录全部证据文件的清单+行数+sha256——复跑差异可归因到文件级(哪个证据在什么时候变了),杜绝"存档数字与复跑数字互异却说不清哪份是真"(LOC 存档 vs 复跑 -70 行这类漂移必须能定位到是哪个文件改动)。
7. **范围声明诚实(FIXED/NOT DONE 分栏)**: 修复轮/冲刺轮的交付清单必须区分 **FIXED**(附三件套)与 **NOT DONE**(附原因+下轮优先级)——时间盒内做不完的能力,公开声明并保留口径不变,比悄悄降级口径或硬塞半成品更保值;凡清单写"完成"的项,必须有对应三件套可查。

## 9. G15 创新可复述门细则 (L9 进攻律的唯一执法器; 实战: 91 分作品的全部残余扣分)

> **为什么需要一道"进攻门"**: R19 终审 91/100(连续金奖)的残余扣分——技术 -2/创新 -3 全部来自评委一句话"**整体形态仍非新范式**"(单机 SQLite+手写 JWT+阈值规则),而完成/叙事 -4 来自演示视图语义残留。防守律(L1-L8)全绿只能保证不被证伪,**满分需要评委的模式归类被打穿**。本门在 P1 定稿前与 P5 收尾时两次执法。

### P1 定稿前: 创新轴打分卡(强制,写入 `01-ideas.md`)

对最终入选 idea 逐轴回答(**每轴必须给出"最接近的已知模式"作为归类证据,不许凭感觉**):

| 轴 | 归类问题 | "没见过"的合格证据形态 |
|---|---|---|
| 立意切口 | 评委是否见过"这个人群×这个痛点"的解法? | 具体到有名字的人群+行业深水区动词(对账/核销/回滚/断言),非"XX 领域 AI 助手" |
| 交互范式 | 评委是否见过这种"用户→结果"的动词链? | 协议级/机器间交互、物理隐喻操作(聚光灯/时间旅行回放/透镜比对),非"填表→出图表" |
| 技术形态 | 评委是否见过这套核心计算组件? | 从 [12 §六 形态升维选型库](12-winning-ui-patterns.md) 至少装配一种(事件溯源回放/流式窗口/图关联/本地推理/协议 server/确定性仿真),有演示帧+钉子测试,评委 30 秒能指出"这个不是 CRUD" |
| 数据构造 | 评委是否见过这种数据资产? | 自造可复现语料/埋雷数据集/跨源对账数据,非"随机生成的假数据" |

**判定规则**: 至少一轴归"没见过"**且**能写出它的 30 秒解释文案(为什么以前做不到/现在怎么做到/演示哪一帧证明),否则 **BLOCKER 回 P1 发散**——此时换方向的成本是 10 分钟,定稿后发现的成本是整个比赛。定稿时把该轴凝结为一句 **retellable moment** 声明(评委看完演示会主动转述给别人的那句话),写入 `01-ideas.md` 并复制进 `03-definition.md` 演示脚本第 1 分钟。

**CORE/ENH 轴定级(防砍尾)**: 定稿的同时,把入选创新轴的能力清单拆成两级并写入 `01-ideas.md` + `run-config.json`:

- **CORE(不可砍)**: 该轴"没见过"成立所依赖的**最小能力集**——砍掉任何一个,评委的归类就从"没见过"跌回"见过"(如"检测层从反馈学习"轴的 CORE=步长随裁决置信度缩放的最小闭环;没有它,轴只剩静态阈值=可归类)。CORE 是作品定义的一部分,**时间盒砍掉 CORE=回 P4 重排(回环类型 `CORE-AXIS`),禁止降级口径交付**;
- **ENH(可砍)**: 加深体验的增强(分维校准/在线权重学习等),砍掉须按 FIXED/NOT DONE 留痕(§8-7),不损伤轴成立。

**排程执法**: P4 时间盒必须预留 **CORE 轴收尾缓冲**——末段 15% 时间只准用于 CORE 轴完成与钉子测试,不允许被防守性修补占用(防守项的边际收益是 0.x 分,CORE 轴的损失是 1-3 分且修复轮代价翻倍)。

### P5 收尾: 复述测试(retell test)

1. 找一位未参与者(子代理/真人皆可),只看演示材料(3 分钟演示脚本+截图+SUBMISSION),不读代码;
2. 要求其用一句话回答"这个作品最厉害的点是什么?";
3. **判定**: 复述内容与 retellable moment 声明**语义一致**(不要求逐字)→ PASS,落 `evidence/retell-test.md`;复述不出/复述成别的东西(通常是工程细节而非创新点)→ 创新未凝结,回 P5 重排演示脚本(把创新帧提到第 1 分钟)或回 P4 给创新轴补演示投影。

### 反模式

- "我们用了 12 种技术"不是创新轴——评委归类的是**核心计算组件**的形态,不是技术清单长度;
- "没见过"但 30 秒讲不懂 = 怪胎轴(减分),必须同时满足可懂性;
- retellable moment 写了但演示第 3 分钟才出现 → 评委前 2 分钟已归类完毕,等于没写。

## 10. G16 演示视图语义门细则 (L1 的视图粒度执法器; 实战: "看起来对"≠"语义上对")

> **为什么需要**: R19 金奖作品仍被抓出的残余完成度/叙事扣分: ①stats/KPI 端点不过滤 e2e 探针(探针跑完、下轮 seed 前,仪表盘"舰队规模"短暂虚高); ②异常检测扫描窗 40h 而设备详情图默认 24h(评委默认视图**看不到 magic moment 的红圈**)。两者都是"数字真实、语义错位"——L1 既有执法器(e2e 差值断言/claim lint)只查"数字真不真",不查"这个视图**声称**展示什么"。本门补齐视图粒度。

### 视图四元组登记表(落 `evidence/view-semantics.md`,P5 建立、P6 复核)

评委在演示路径上会看到的**每个**视图(页面/图表/KPI 卡/徽章/导出文件)登记一行:

| 视图 | 数据源端点 | 过滤条件 | 时间窗 | 单位口径 |
|---|---|---|---|---|
| (例)舰队 KPI 卡 | GET /api/v1/fleet/stats | `tags !~ 'e2e'` 与页面列表**同一过滤** | 实时 | 台,货币分→元 |

逐项对账三条红线(任一不符 = BLOCKER):

1. **过滤完备**: 探针/e2e/审计辅助数据在**所有**演示视图(list/stats/KPI/详情/导出)同过滤——过滤只做在某个页面而 stats 端点不过滤=最常见缺口;e2e 必须有一条断言"注入探针前后,演示视图值差=0";
2. **窗口覆盖**: 演示**默认**窗口 ≥ 检测/扫描/对比窗(扫描 40h 则默认视图 ≥ 40h,或提供"跳到异常点"一键定位)——magic moment 所需的证据在评委打开的第一屏必须可见;
3. **单位口径**: 视图标注单位与 API 字段单位一致(分/元、ms/s、z 值/百分比、UTC/本地),跨视图换算单点实现。

### 反模式

- "数字是对的"辩护无效——本门判的是**视图语义**(该视图声称的集合/窗口/单位),不是数字真值;
- 只登记页面不登记 stats/导出/徽章(非页面投影同样是评委视图);
- 四元组登记后后端改了过滤,登记表未同步(P6 复核即抓)。

## 11. G17 活性一致性门细则 (L1 的时点粒度执法器; 实战: "提交之后,数字开始说谎")

> **为什么需要**: G14 claim lint 在**提交时点**对账,但评审不是瞬时行为——评委会在提交后 N 小时打开作品、注入自己的探针流量、复跑门槛;期间运行态一变(评委注入 1 笔交易/探针跑完/时间流逝),一切手敲在文档里的数字(总数/保护 N 笔/测试数/端点数)集体失真。R20 实测: 文档手敲"当前库 1549"在评委注入 1 笔后即为假,而**没有任何静态检查能抓住**——只有"从运行态重算↔文档对账"的活门能抓。本门把"对账"从时点检查升维为**随评审存活的机制**。

### 规则(提交物必须自带活门)

1. **`--check` 活门命令**: 提交物必须提供一个评委可直接运行的检查命令(如 `python scripts/sync_counts.py --check`),它 **从运行态(DB/API/测试套件实时重算)** 全部对外声明的数字,并与**全部承载这些数字的文档**(SUBMISSION/README/demo-script/qa)逐处对账;
2. **可指认性**: 漂移时输出必须指认到**文件+句子级**("demo-script.md 第 3 段 '保护 1548 笔' 声明 1548,运行态重算 1549"),并把**重算值与声明值的来源分清**(是"recomputed"还是某中间文件),非零退出;对账通过输出 OK+exit 0;
3. **单源写入门**: 同一数字的文档侧更新只允许一个机制(自动写入块/单源生成),手敲数字存活=门的红测对象——`--write` 模式一键刷新全部文档数字;
4. **红测铁律(L6)**: 活门自身必须被红测过一次——亲手篡改任一文档数字,亲见 `--check` 变红并精确指认该句,还原后转绿,留 `evidence/live-consistency-check.log`;
5. **同族同源口径**: 活门探针读运行态时,凡同一事实存在第二个机械工具也在数(如 verify_project 匿名全扫报的操作数),**探针必须复用该工具的白名单/算法**——两个“各自为真”的口径(40 vs 38)在评委眼里就是漂移证据;若必须异源,口径差要在文档显式声明;
6. **评审期活性**: 活门盯运行态而非提交快照——评委注入自己的流量后再跑 `--check`,门对**评委造成的漂移**同样指认(这正是它优于静态 lint 的地方: "门会咬评审"本身成为可演示的可信度时刻,可在 demo-script 中安排 30 秒展示)。
7. **兼容开关必须反向钉住**: 若因兼容旧调用给门加开关(如 `prose=False` 只查部分族),同轮必须:①grep 全部调用点显式化;②加一条钉子断言“开关默认开启/关闭时该族不被检查”——防后人顺手关成静默拆除(L6)。

### 反模式

- 只在 CI 里跑一次的静态对账(时点≠活性);
- 指认输出只说"存在漂移"不说哪句错(不可指认=不可修复);
- 手敲数字与生成块混存,`--check` 只覆盖生成块(覆盖面必须=全部对外数字);
- 活门从未被红测("我写了 check 脚本"≠门活着);
- 探针与门槛工具对同一事实各用一套白名单(评委看到双口径即漂移)。
